# task-009 W2 URL 가져오기 SSRF 방어 (Worker fetch-url)

| 항목 | 내용 |
|---|---|
| 웨이브 | W2 |
| 선행 | task-010, task-029 (유튜브 뒤로, ADR-0006 결정 4. 완료 시 task-011의 URL 본문 추출을 연결) |
| 위험도 | 높음 |
| 보안 영향 | 노출 면 (외부 URL 요청, 내부망 접근 위험) |
| 담당 | builder (+ tester). 착수 전 challenger. 완료 후 reviewer(security) |
| 근거 | `docs/01_PRD.md#8`, `docs/01_PRD.md#8-1`, `docs/04_API.md#A-04`, `spec S-09` |
| 쓰기 허용 | `apps/worker/src/fetch-url/**`, `apps/web/src/lib/fetch-url/**`(URL 형식 사전 검증만), 해당 테스트 |

## 할 것
- 외부 URL 요청은 Worker의 `fetch-url` 모듈에서만 수행(웹 서버는 요청하지 않음). 선행 task-010의 Worker 골격·네트워크 격리 위에 구현
- URL 검증: http(s)만, 해석된 IP 기준 검사(사설·루프백·링크로컬·메타데이터 주소 차단), DNS 재바인딩 방지(검사한 IP로 연결), `HTTP_PROXY` 등 프록시 환경 변수 무시
- 리디렉션 최대 5회, 매 회 재검사; 응답 10MB·15초 제한; 본문은 비신뢰 텍스트로 저장
- 차단 시 422 + 사유 코드 로그(응답 본문 제외); URL 수집 등록 경로(A-04 url, task-008)에 연결

## 하지 않을 것
- 차단 목록(문자열) 방식 단독 사용, 헤드리스 브라우저·JS 렌더링, 응답 본문 로그

## 완료 조건 (실행 가능한 확인)
- [ ] 단위 테스트: 127.0.0.1·10.x·169.254.169.254·IPv6 루프백·`localhost` 차단
- [ ] 단위 테스트: `::ffff:127.0.0.1`·`0.0.0.0`·`100.64.0.0/10`·`fc00::/7`·10진수 IP(예 2130706433) 차단
- [ ] 테스트: `HTTP_PROXY`/`HTTPS_PROXY`를 설정해도 검사 우회 불가
- [ ] 테스트: 외부 URL이 내부 주소로 리디렉션되면 차단, 6회 리디렉션 차단
- [ ] 테스트: 10MB 초과·15초 초과 중단
- [ ] `pnpm test` 통과, `secscan` 신규 의존성 라이선스 이상 없음
