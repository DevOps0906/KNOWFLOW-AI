# ADR-0001 자료 매체 확장 순서와 사전 설계

- 상태: 제안
- 날짜: 2026-11-02

| 항목 | 내용 |
|---|---|
| 맥락 | Readray·NotebookLM은 PDF·웹 외에 YouTube·오디오·영상·Office·HWP·이미지·연동을 받는다([benchmark-media.md](../benchmark-media.md)). MVP는 PDF·URL만 받지만, 나중에 매체를 늘릴 때 스키마·API를 다시 짜지 않아야 한다. |
| 선택 | ① 개발은 PRD 3-1 로드맵 순서(문서 → 음성·영상 → 연동)로 미룬다. ② 지금은 `sources.source_type`에 예약 값을 두고, 인용 위치를 `locator` jsonb(페이지·문자 범위 → 이후 시각·슬라이드·영역)로 일반화한다. ③ 처리는 매체별 파이프라인 단계 표로 확장하고, API는 미지원 유형에 422 "지원 예정"을 돌려준다. |
| 대안 | 매체별 전용 테이블: 인용·검색이 갈라져 질의응답이 복잡해진다. MVP부터 다매체: 일정·비용(전사·OCR)·약관 위험이 커진다. |
| 결과 | 얻는 것: 확장 시 마이그레이션 최소화, 인용 UI 하나로 시각·페이지 모두 표시. 잃는 것: locator 형식 검증을 코드로 해야 한다. 되돌리는 비용: 낮음(예약 값 제거). |
