# ADR-0003 호스팅·업로드 경로·신뢰할 IP 헤더

- 상태: 채택 (2026-11-02, task-002 착수 전 challenger 지적 반영)
- 날짜: 2026-11-02

| 항목 | 내용 |
|---|---|
| 맥락 | Worker 상시 실행, 큰 PDF 업로드, IP 기준 요청 한도, 서비스 키 격리를 동시에 만족하는 배치가 필요하다. 이 계정에는 Vercel·Supabase 연결이 있다. |
| 선택 | 아래 표. 비용은 모두 `미확인`(베타 사용량 측정 후 갱신). |
| 대안 | 웹+Worker 한 플랫폼(Vercel은 상시 컨테이너 불가), Worker를 Supabase Edge Functions로(실행 시간 제한), 업로드를 Route Handler로 받기(Vercel 함수 요청 본문 4.5MB 한도). |
| 결과 | 웹·DB는 관리형으로 단순하다. 대신 Worker 외부 연결 통제는 플랫폼이 아니라 앱 코드·프로세스 분리로 한다. 되돌리는 비용: Worker 호스팅 교체는 낮음(컨테이너), 웹 호스팅 교체는 중간. |

| 항목 | 결정 |
|---|---|
| 웹 호스팅 | Vercel. 함수 리전 = DB 리전(서울 `icn1`). Vercel 앞에 다른 프록시를 두지 않는다 |
| DB·Storage·Auth | Supabase, 리전 서울(ap-northeast-2) |
| Worker 호스팅 | Fly.io 컨테이너, Worker 전용 Fly 조직(다른 앱과 내부망 분리). 리전은 서울과 가장 가까운 곳(서울 리전 유무 `미확인`) |
| Worker DB 연결 | 세션 모드 연결(pgmq 세션 기능 필요). 웹은 트랜잭션 풀러 |
| Worker 외부 연결 통제 | 플랫폼 방화벽 기능 `미확인` → 앱 코드에서 강제: 공개 URL은 허용하되 해석된 IP 기준으로 사설·메타데이터·루프백 차단(리디렉션마다), 사설망 허용은 DB·임베딩 서버만. PDF 파싱은 네트워크·비밀 없는 하위 프로세스 |
| 신뢰할 IP 헤더 | `x-real-ip`(Vercel이 설정). 헤더가 없으면(로컬 등) 요청 한도는 사용자 ID 기준으로만 적용. IPv6는 /64 단위로 묶는다. 로그인 한도는 IP와 이메일 둘 다 기준(CGNAT 오탐 완화) |
| 업로드 경로·본문 한도 | 브라우저 → Supabase Storage 서명 업로드 URL 직접. 크기·형식 강제 = 버킷 `file_size_limit`(50MB)·`allowed_mime_types`(PDF)(task-008) + 등록 시 서버 검증 |
| 임베딩 서버 위치 | task-013(ADR-0004)으로 넘김 |
