# CONVENTIONS — 공통 표기·금액·개인정보 규칙 (정본)

## 금액
| 항목 | 규칙 |
|---|---|
| 단위 | 모든 금액은 **정수 원** |
| 계산 | 행 금액 = 수량 × 단가 − 할인액. 공급가액 = 행 금액 합(할인 후) |
| 세액(VAT) | 세액 = 공급가액 × 세율, **문서 단위 1회 원 미만 버림**. 합계 = 공급가액 + 세액. 세 값을 컬럼으로 따로 저장 |
| 면세 | 세액 0. 세율 기본값(10%)은 법령 확인 전까지 **미확인** |
| 표시 순서(CRM 견적) | 품목 합계 / 할인 / 공급가액 / VAT / 합계 |

## 개인정보·마스킹
| 항목 | 규칙 |
|---|---|
| ★ | 개인정보 필드 표시(문서·화면·표). 이벤트 payload에 이메일·IP·전화 원문을 넣지 않고 해시 + 조회 키만 |
| 주민등록번호 | 저장 전 뒷자리 자동 마스킹, 원문 저장 금지 *(개인정보보호법 제24조의2 확인 필요)*. 저장 금지는 본인인증 도입 시에도 동일(CI/DI 해시 중심) |
| 카드번호 | 앞·뒤 일부만 남기고 가운데 마스킹 *(확인 필요)* |

## 표기
| 항목 | 규칙 |
|---|---|
| "확인 필요" | 법령·시장·수치를 원문으로 확인하지 못했으면 *(확인 필요)* 또는 **미확인**으로 쓰고 근거를 요구한다. 확인 전에는 사실로 쓰지 않는다 |
| 이벤트 이름 | `domain.object.verb` (예: `payment.order.paid`) |
| 제안값 | 확정이 아닌 값은 "제안"으로 표시 |

## 데이터 무결성·내보내기 (2026-10 추가 — crm·erp·lms 보안 리뷰)
| 규칙 | 내용 |
|---|---|
| 조직 간 연결 금지 | 다른 테이블을 가리키는 id(company_id·deal_id·담당자 id·course_id 등)는 같은 org의 행이어야 한다. 복합 FK(org_id, id) 또는 쓰기 RPC 안에서 org 대조. 위반은 404(존재 노출 금지). |
| API = RLS | 쓰기 권한 조건(담당자·관리자 등)은 API와 RLS 정책에 똑같이 건다. 불변 규칙(발행 후 수정 금지·닫힌 문서)은 DB 트리거로도 막고 쓰기는 RPC 전용. |
| 동시성 | 잔량·횟수·한도를 확인하고 쓰는 작업은 같은 트랜잭션에서 대상 단위 잠금(행 잠금 또는 advisory lock) 후 계산한다. |
| CSV 수식 주입 | 내보내는 CSV 셀이 `=` `+` `-` `@` 탭·CR로 시작하면 앞에 `'`를 붙인다(가져오기도 같은 검사). |
| 개인정보 대량 내보내기 | 관리자 한정 · 사유 입력 필수 · 건수·필터·사유를 audit_log에 기록 · 한 번에 최대 10,000행(제안값) · 결과 링크 24시간·1회. |
