# ADR — 파일 저장소·업로드·바이러스 검사 선택

- 상태: 채택 · 버전·라이선스·정책 확인일 **2026-10** (공식 문서 재확인 전 수치는 사실로 쓰지 않는다)
- 맥락: 플랫폼 규칙은 Supabase Storage 경로 `org_id/app/entity/uuid.ext`와 버킷 3종(`platform-docs/products/_platform-core/CORE_SPEC.md#10`, `storage_org_id` 헬퍼는 core_lite). STT·RAG·OCR 같은 모듈은 입력 파일을 이 모듈의 file_id로만 받는다.

## 선택
1. **저장소: Supabase Storage**(Apache-2.0) — 조직 RLS를 경로 첫 폴더로 판정. 6MB 초과는 **tus 재개 업로드**, 클라이언트는 Uppy(MIT) 사용 가능.
2. **검증: 서버 측 이중 검사** — 확장자 허용 목록 + 매직 바이트 + 크기, sha256은 서버 계산. 검사 통과 전에는 다운로드·공유 불가.
3. **바이러스 검사: ClamAV(GPL-2.0)를 별도 서비스로 호출**(내부망 프로세스, 우리 코드와 링크·임베드 없음).

## 대안
| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| S3 호환(MinIO 등) | 표준 API, 멀티파트 업로드 | MinIO는 AGPL-3.0(확인 필요), Supabase RLS와 별도 권한 체계 필요 | 보류(자체 호스팅 요구가 생길 때) |
| 서버 경유 업로드(API가 본문 중계) | 서버가 전 바이트를 직접 검증 | 대용량 시 서버 부하·메모리, 재개 업로드 직접 구현 | 제외 |
| 스캔 없이 확장자·크기만 | 구현 단순 | 악성 파일 공유 위험 | 제외(스캔은 MVP 포함) |
| 상용 AV·클라우드 스캔 API | 운영 부담 적음 | 파일 외부 전송 고지·국외 이전 검토 필요, 비용 확인 필요 | 선택 대안(고객 요구 시) |

## 결과
- **라이선스 메모 — 확인 필요**: ClamAV는 GPL-2.0이다. 별도 프로세스로 네트워크 호출만 하고 소스를 포함·링크하지 않는 구조를 유지한다. 컨테이너 이미지를 제품에 번들해 배포하는 경우의 의무는 법률·라이선스 검토 전까지 확정하지 않는다.
- ClamAV는 시그니처 DB를 주기 갱신해야 하며(운영 부담), 서비스 장애 시 파일이 `scanning`에 머문다 — 재시도·운영 알림으로 대응(`api.md` 검사 워커).
- 결정: SVG·HTML은 업로드 허용하되 인라인 표시 금지(항상 attachment, Content-Type 고정, SVG 미리보기는 래스터 변환본만). 압축 파일 허용, 내부 검사는 ClamAV 한도(제안: 해제 크기 500MB·깊이 3, 초과는 격리) — 수치는 보안 검토 후 확정(확인 필요).
- 확인 필요(2026-10): ClamAV 현재 버전·LTS(1.4 · 1.5 계열 날짜 미확인) · tus 구현체(tusd 등) 버전 · Uppy 버전 · Supabase Storage 요금·tus 한도 · 국내 리전 저장 가능 여부.
