# Files Storage 모듈 — 파일 저장·공유 청사진

**업로드 세션을 서버가 먼저 만들고 → 파일이 Storage로 직접 올라가고(6MB 초과는 tus 재개) → 서버가 형식·크기·해시를 검증하고 → 바이러스 검사가 끝나야 사용·공유할 수 있고 → 버전·첨부 참조·공유 링크·휴지통까지 → 결과를 이벤트로 다른 모듈에 알리는** 구조입니다.
이 폴더는 기획 표(`screens.md` · `api.md` · `data.md`)라서 `plan2spec`이 바로 구조도 · 와이어프레임 · 필수 구조 검사를 만듭니다. 저장소·검사 엔진 선택 근거는 `adr.md`.

```bash
nomad-os module add files-storage <프로젝트 경로>   # → <프로젝트>/docs/blueprints/files-storage/ 로 가져오기
plan2spec                                           # 화면 9개 · 흐름 5개 와이어프레임 + 구조도 생성
```
쓰지 않을 화면 · API · 테이블은 **행을 지우면** 됩니다. ID 접두사 `FILE-`. 단독으로 동작하며, 다른 모듈은 3절의 **외부 계약 이벤트**와 `file_id`만 사용합니다.
필요 모듈: contracts

## 2. 상태
```
파일:  uploading → scanning → ready
                          ↘ quarantined(탐지) → 관리자 재검사 요청 → 통과 시에만 ready(수동 해제 금지·감사 기록)
       ready·quarantined → deleted(소프트 삭제, purge_after = 30일 후) → 영구 삭제(객체 삭제, purged_at)
공유:  active → revoked | expired(만료·다운로드 한도 소진)
버전:  uploading → scanning → ready | quarantined (현재 버전은 새 버전이 ready가 될 때만 교체)
```
- **ready 전에는 다운로드·공유·참조 연결 불가**(423). 검사 서비스 장애는 `scanning` 유지 + 재시도.
- 업로드 검증 실패(확장자·내용 불일치·크기)는 객체를 지우고 deleted로 기록.
- 복구(휴지통 → 원래 상태)는 보관 기간 안에서만, 영구 삭제 후에는 불가(410).
- 파일 상태에 `purged`(영구 삭제됨, 복구 불가)가 있다. 서명 URL은 **대상 버전이 ready일 때만** 발급, 버킷 직접 SELECT는 RLS로 금지.
- 공유 다운로드는 상태 재확인 + 한도 차감 + 서명 URL 발급(만료 60초)을 한 트랜잭션에서 하고 발급 실패 시 롤백. 비밀번호 링크는 인증 전 파일명·크기를 숨긴다. 흐름 세부는 `api.md` 서버 내부 규칙.

### 파일별 접근 제어 (owner_module · visibility)
FILE은 **저장·검사·서명 URL 발급**만 맡고, 모듈 고유의 "누가 이 파일을 볼 수 있나"는 소유 모듈이 판정한다. owner_module·visibility 구분표와 서버 간 호출 규칙은 [../contracts/ACCESS.md](../contracts/ACCESS.md)("서버 간 인증과 파일별 접근"). 이 모듈의 동작: `owner_module`이 있는 파일은 파일함 목록(A03)·사용자 다운로드(A05)·공유(A08)에서 제외하고, 소유 모듈의 서버 간 호출만 A05 서명 URL을 받는다(소유 모듈 규칙 예: stt 비공개 녹음, rag owner_only 문서, ocr 주민번호 원본).

## 3. 규칙 요약
| 항목 | 규칙 |
|---|---|
| 경로·버킷 | `org_id/app/entity/uuid.ext`(CORE_SPEC#10), 기본 `org-files`(50MB) · `exports`(서명 URL) · `public-assets`(래스터 이미지 png·jpg·webp·gif만 10MB, SVG·HTML 거부). 버킷 직접 SELECT 금지, 서명 URL로만 읽음. 조직별 조정은 `file_settings` |
| 업로드 | 세션 발급(A01) → Storage 직접 업로드(tus 재개) → 완료 검증(A02): 확장자 허용 목록 + 매직 바이트 + 크기 + sha256. 업로드 토큰은 1회용(complete 시 무효), 새 업로드는 항상 새 경로라 검사·해시는 같은 객체 버전에만 적용(TOCTOU 차단) |
| 검사 | ClamAV 별도 서비스(GPL-2.0, 라이선스는 `adr.md` — 확인 필요). 통과 후 ready + `file.object.ready` |
| 버전 | MVP는 덮어쓰기 시 이전 버전을 **보관만**(복원·정리 UI 없음) |
| 중복 | 같은 sha256은 안내만, 저장 공유(dedupe)는 이후 |
| 공유 | 토큰은 해시만 저장·원문은 생성 응답에서 한 번만, 만료·최대 다운로드 수·선택 비밀번호, 조직 정책이 상한 |
| 미리보기 | 이미지 썸네일·PDF 첫 장을 비동기 잡으로 생성, 실패해도 파일 사용 가능 |
| 이벤트 | `file.object.ready` · `quarantined` · `deleted` · `purged` — 공통 봉투·전달 규칙: [../contracts/EVENTS.md](../contracts/EVENTS.md), payload는 `api.md` 외부 계약. `file.object.ready`는 `version_no`를 포함하고, 받는 쪽은 같은 file_id의 버전이 바뀌면 재처리 |

## 4. 다른 모듈과의 경계
| 모듈 | 관계 |
|---|---|
| STT · RAG · OCR | 입력 파일은 `file_id`로만 받는다. `ready` 이벤트 이후 처리, 자기 파일은 `owner_module`로 소유하고, 접근 규칙 판정 후 서버 간 인증으로 FILE-A05(서명 URL)를 요청. 결과 파일은 이 모듈에 올리고 연결(FILE-A07) |
| LMS · 그 외 첨부가 필요한 모듈 | `file_links`(ref_module·ref_id)로 참조만. 파일 삭제는 `file.object.deleted`로 알려 각자 정리 |
| auth-rbac | `files:manage` 권한·`has_permission` 사용(미설치 시 core 헬퍼). 서비스 키는 워커·참조 모듈 서버만 |
| admin-audit | 같은 이벤트 + 다운로드·공유 접근을 `audit_log`로 기록(event_id 유니크) |
| notify | 격리 발생 시 업로더·파일 관리자에게 안내(구독은 notify 쪽 설정) |
| payments · ERP | 직접 관계 없음. 용량 쿼터 과금은 이후 |

## 6. 보안 (security-baseline 연결 — 위협 메모)
이 모듈은 **인터넷에 노출되는 면이 있다**(공유 링크 A10, 업로드 URL·토큰 A01, 서명 URL 다운로드 A05, 서버 간 A01·A05·A07). 보안 레벨은 PRD 8절에서 정하되 L1 이상 권장.
| 항목 | 결정 |
|---|---|
| 노출 면 | `GET·POST /api/public/shares/[token]`(공개), Storage 업로드 엔드포인트(서명 토큰), 서명 URL 다운로드, 서버 간 호출, 관리자 화면(/admin/files) |
| 인증·인가 | 같은 조직 구성원만 파일 접근(RLS + `storage_org_id`). 삭제·공유는 업로더·파일 관리자. 서버 간은 서비스 키 + 키의 org·ref_module 일치(불일치 404). 공유는 토큰 + 선택 비밀번호 |
| 다루는 데이터 | 파일 본문(개인정보·민감정보 포함 가능) · 표시 이름★ · sha256 · 공유 비밀번호 해시★ |
| 필요한 키·권한 | 서비스 키(워커·참조 모듈) · Storage 서명 비밀(플랫폼 관리) · ClamAV 서비스 호출 토큰(내부망) · 이벤트 서명 비밀키(구독자별) |
| 입력 | 클라이언트 경로·mime·sha256은 신뢰하지 않음(서버가 경로 생성·매직 바이트 판정·해시 계산). 파일명은 정규화해 표시용으로만 사용, 경로 조합 금지 |
| 체인 | 악성 파일 업로드 → 공유 링크로 외부 확산 → 검사 통과 전 공유·다운로드 차단 + 격리. 공유 토큰 유출 + 비밀번호 없음 → 정보 유출 → 만료·다운로드 한도·폐기 + 정책으로 비밀번호 필수 가능. HTML·SVG 다운로드 → 브라우저 실행(XSS) → 항상 attachment + nosniff + Content-Type 고정, SVG 미리보기는 래스터 변환본만 |
| 피해 범위 | 서비스 키 유출 시 조직 파일 열람·삭제 → 키 범위(org·ref_module) 제한·교체. 서명 URL 유출은 만료 시간만큼 → 짧은 만료 |
| 남용 | 업로드 세션·공유 비밀번호 시도·공유 다운로드에 레이트 리밋(429). 조직 용량 한도. 공유 비밀번호 연속 실패 시 잠시 차단 |
| 로그 | 업로드·다운로드·공유 생성·폐기·삭제·격리·정책 변경을 감사 이벤트로 기록. 토큰 원문·비밀번호·서명 URL·파일 본문은 로그 금지 |
| 결정 | 공개 전 검사 필수. 경로는 서버가 생성. 토큰은 해시 저장. ClamAV는 별도 서비스(`adr.md`). 이벤트는 서명 + event_id 멱등 + sequence |
