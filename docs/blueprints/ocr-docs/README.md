# OCR Docs 모듈 — 문서 인식·필드 추출 청사진

**파일을 올리면 → 전처리·OCR로 글자와 위치를 읽고 → 문서 종류별 필드를 추출·검증하고 → 신뢰도 낮은 값은 사람이 원본과 나란히 보고 고쳐 확정하고 → 확정 결과를 이벤트로 다른 모듈에 알리는** 구조입니다. 자동 확정은 없습니다(사람이 확정해야 확정).
이 폴더는 기획 표(`screens.md` · `api.md` · `data.md`)라서 `plan2spec`이 바로 구조도 · 와이어프레임 · 필수 구조 검사를 만듭니다. 엔진 선택 근거는 `adr.md`.

```bash
nomad-os module add ocr-docs <프로젝트 경로>   # → <프로젝트>/docs/blueprints/ocr-docs/ 로 가져오기
plan2spec                                      # 화면 8개 · 흐름 4개 와이어프레임 + 구조도 생성
```
쓰지 않을 화면 · API · 테이블은 **행을 지우면** 됩니다. ID 접두사 `OCR-`. 입력 파일은 files-storage의 `file_id`로만 받고(미설치 시 Supabase Storage 경로 규칙 CORE_SPEC#10), 다른 모듈은 3절의 **확정 이벤트**만 구독합니다.
필요 모듈: contracts, files-storage

## 2. 상태와 파이프라인
```
문서:  queued → processing → needs_review → confirmed
                    ↘ failed(다시 인식 가능)    ↘ rejected(검토자 반려)
       failed → queued · needs_review → queued  (재인식 = OCR-A07, 새 작업·이력 보존)
작업:  queued → running → succeeded | failed | cancelled   (running → queued 자동 재시도 최대 3회)
       file.object.deleted 수신 시 queued·running 작업은 cancelled, 문서는 failed(원본 삭제됨)
```
| 단계 | 내용 |
|---|---|
| 1 접수 | OCR-A01: file_id 확인(검사 통과·ready만) → 문서·작업 생성 |
| 2 전처리 | 회전·기울기 보정 · 해상도 제한 · PDF 분해 |
| 3 OCR | 단어·좌표·신뢰도(기본 PaddleOCR, 설정으로 변경) |
| 4 마스킹 | **OCR 직후 · 추출 앞**: 주민등록번호 패턴 뒷자리 마스킹(원문 저장 금지, 확인 필요). 감지되면 문서에 감지 표시 + 감지 좌표를 가린 **마스킹 사본 이미지** 생성. 감지 문서는 LLM 보조를 끄거나 자체 호스팅 경로만 사용 |
| 5 추출·검증 | **규칙 우선**(마스킹된 텍스트 기준), LLM 보조는 설정이 켜진 경우만(감지 문서 제한은 4단계). 사업자번호 체크섬 · 날짜·금액 형식 |
| 6 확인 | 신뢰도 기준 미만·검증 실패 필드를 강조, 원본과 나란히 수정 → 확정(OCR-A05) |
| 7 알림 | `ocr.document.confirmed`를 같은 트랜잭션에서 outbox에 기록 → 구독자별 전달 |
- 문서 종류(기본 3종): **영수증**(상호·일시·합계·부가세 등), **사업자등록증**(사업자번호·상호·대표자·개업일 등), **일반 계약서**(전문 텍스트 + 핵심 필드 당사자·기간·금액). 종류별 필드는 `ocr_doc_types` 스키마로 정하며 기본 필드 목록은 설정 화면(OCR-S05)에서 확정.
- 확정 문서·반려 문서는 수정 불가(409). 다시 인식(OCR-A07)은 failed·needs_review 문서만 가능하며 이력을 남기고 새 작업을 만든다.
- **원본 저장·표시**: 원본은 files-storage에 `owner_module=ocr`로 저장(파일함 노출 없음). 주민번호 감지 문서의 화면 표시는 **마스킹 사본**이 기본, 원본은 `ocr:review` 이상 + 사유 입력 시에만 열람(열람 감사 기록 · 다운로드 금지). 감지되지 않은 문서는 업로더도 원본 열람 가능.
- **원본 보관(통일)**: **확정 시 원본 자동 삭제가 기본**(설정으로 끌 수 있음). 설정의 보관 기간(기본 30일)은 **미확정·반려 문서의 상한**.

## 3. 이벤트 (다른 모듈과의 경계)
| 항목 | 내용 |
|---|---|
| 발행 | `ocr.document.confirmed` — payload는 document_id · doc_type · doc_type_version · fields_ref · confirmed_by(id만). 공통 봉투·전달 규칙: [../contracts/EVENTS.md](../contracts/EVENTS.md) |
| 값은 재조회 | payload에 필드 값·연락처를 넣지 않는다. 받는 쪽이 서버 간 인증으로 OCR-A03을 조회해 읽는다 |
| 자동 반영 금지 | 받는 모듈은 확정 값을 **등록 후보**로 만들고 사람이 확인해 등록한다 |
| 소비 측 미정의 | 소비 측(erp · crm) 구독은 **아직 정의되지 않음** — 각 모듈이 자기 외부 계약에 추가할 때 연결한다. 아래는 예시 |
| files-storage 수신 | `file.object.deleted` 수신 시 해당 file_id의 처리 중 작업은 cancelled · 문서는 failed로 전이 |

**구독 예시** (구독 구현은 해당 모듈 몫 — 이 모듈은 erp · crm을 수정하지 않는다)
| 구독자 | 받는 type | 쓰는 곳 |
|---|---|---|
| ERP | `ocr.document.confirmed`(doc_type = 사업자등록증 · 영수증) | 구매·매입 영역의 거래처(`partners`) 등록 후보 · 매입 입력 보조. 거래처 사업자번호는 ERP가 10자리 형식 검증(erp/README 매입·거래처 장) |
| CRM | `ocr.document.confirmed`(doc_type = 사업자등록증) | `crm_companies` 등록 후보. 사업자번호(정규화·org 내 유니크)로 중복 후보 확인(crm/data.md) |
| admin-audit | 전체 | `audit_log` 기록(event_id 유니크) |

## 4. 엔진 정책 요약
| 항목 | 규칙 |
|---|---|
| 기본 | PaddleOCR 3.x 한국어 모델 자체 호스팅(Apache-2.0) — 문서 이미지가 외부로 나가지 않는다 |

| 제외 | Surya — 코드 GPL · 가중치 사용 조건 제한(확인 필요). 상세 `adr.md` |
| LLM 보조 | 기본 끔. 켜면 `resolve_ai_route`로 모델 경유, 문서 내용은 데이터로만 취급. 주민번호 감지 문서는 끄거나 자체 호스팅 경로만 |

## 6. 보안 (security-baseline 연결 — 위협 메모)
이 모듈은 **파일을 받아 처리하는 면**이 있다(OCR-A01) · 이벤트 서버 간 조회 면(OCR-A03). 보안 레벨은 PRD 8절에서 정하되 L1 이상 권장.
| 항목 | 결정 |
|---|---|
| 노출 면 | 업로드·처리 API(로그인), 서버 간 조회(OCR-A03 서비스 키), 관리자 화면(/admin/ocr) |
| 인증·인가 | 같은 org + `ocr:*` 권한, 문서는 업로드한 본인·검토자만. 서버 간은 서비스 키의 org와 문서 org 일치(불일치 404) |
| 다루는 데이터 | 문서 이미지·추출 값(사업자번호·대표자명·금액 등)★. 주민번호 원문은 필드·단어 JSON에 없음(OCR 직후 마스킹). 원본 이미지에는 남을 수 있어 감지 문서는 review 권한 + 사유 + 열람 감사로 제한 |
| 필요한 키·권한 | 서비스 키(워커 전용) · 이벤트 서명 비밀키(구독자별) · CLOVA OCR 키(선택 시 서버 환경변수만) |
| 입력 | 파일은 files-storage의 검사 통과(ready) 파일만, 형식·크기·페이지 수 제한. OCR 텍스트는 데이터로만 취급(프롬프트 주입 방지) |
| 체인 | 악성 PDF → 전처리 단계 공격 → 처리 워커를 격리(리소스·시간 제한, 네트워크 차단) |
| 남용 | 업로드·재인식에 레이트 리밋, 크레딧 선차감(선택), 시도 한도 3회 |
| 로그 | 문서 id·상태 전이·확정·수정자만 기록. 추출 값·원본 텍스트·키는 로그 금지 |
| 결정 | 사람이 확정해야 확정. 값은 이벤트에 싣지 않고 재조회. 마스킹은 저장 전에 |

## 9. 확정된 결정 · 팀장 결정 필요
확정: 기본 엔진 PaddleOCR 자체 호스팅 · 문서 종류 3종 · 사람 확정 필수 · 주민번호 저장 전 마스킹 · 확정 이벤트에 값 미포함(id만).
확정(팀장): 신뢰도 기준 기본 0.85(제안값 · 문서 종류별 조정) · 원본 보관: 확정 시 자동 삭제가 기본 · 30일(설정)은 미확정·반려 문서 상한 · 주민번호가 감지된 원본 이미지는 `ocr:review` 이상 + 사유 입력 시만 열람 · 다운로드 금지 · 열람 시 감사 기록 · 화면은 마스킹 사본 기본 · CLOVA OCR 기본 비활성(조직 관리자가 외부 전송 고지에 동의한 뒤 켬) · 자체 벤치마크 샘플은 문서 종류당 50장(제안값).
팀장 결정 필요: 없음(법·수치는 "확인 필요" 유지).
