# STT Voice 모듈 — 음성 받아쓰기 청사진

**음성을 올리거나 녹음하고(동의 기록) → 서버가 5분 조각으로 나눠 whisper로 병렬 받아쓰기 → 병합(선택: 화자 구분·요약) → 사람이 편집·내보내기 → 완료를 이벤트로 다른 모듈에 알리는** 구조입니다.
이 폴더는 기획 표(`screens.md` · `api.md` · `data.md`)라서 `plan2spec`이 바로 구조도 · 와이어프레임 · 필수 구조 검사를 만듭니다. 엔진·모델 선택 근거와 한국어 정확도 벤치마크 절차는 `adr.md`.

```bash
nomad-os module add stt-voice <프로젝트 경로>   # → <프로젝트>/docs/blueprints/stt-voice/ 로 가져오기
plan2spec                                       # 화면 10개 · 흐름 5개 와이어프레임 + 구조도 생성
```
쓰지 않을 화면 · API · 테이블은 **행을 지우면** 됩니다. ID 접두사 `STT-`. 입력 음성은 files-storage의 `file_id`로만 받고(미설치 시 Supabase Storage 경로 규칙 CORE_SPEC#10), 권한은 auth-rbac `has_permission`을 씁니다(미설치 시 core `is_org_member`·`has_org_role`). 다른 모듈은 `api.md` 외부 계약의 **이벤트**만 구독합니다.
필요 모듈: contracts, files-storage

## 2. 상태
```
작업:   queued → running → succeeded | failed | cancelled
        running → queued (자동 재시도: attempts < max_attempts)   queued → cancelled
단계:   pending → running → succeeded | failed | skipped | cancelled
녹음:   queued → processing → done | failed      (최신 transcribe 작업을 따라간다)
        done → queued (재받아쓰기: 편집 잠금)   processing → done (재작업 실패·취소 시 이전 현재본 유지, 잠금 해제)
원본:   보관 중 → 삭제됨 (retain_until 도래 · 즉시 삭제 · 녹음 삭제)
```
- **전사 확정**: 작업 성공 시 한 트랜잭션(전사 version+1 · 구간 · 화자 · 이벤트 outbox). 재받아쓰기는 새 version이고 이전 version은 유지해 사람 수정본을 덮지 않는다.
- 사용자의 "다시 시도"는 새 작업을 만든다(규칙: [../contracts/JOBS.md](../contracts/JOBS.md)). 실패한 작업은 failed로 남는다.
- 편집은 녹음 상태 done일 때만. **재받아쓰기로 done → queued가 되면 작업이 끝날 때까지 편집 잠금**(편집 저장은 409). 시작·끝 시간은 수정할 수 없고 텍스트·화자만 바꾼다(원문 복원 가능).
- **접근**: 작성자 본인(기본 private) · 조직 공유 시 구성원 읽기. 음성 관리자는 설정·용어집·사용량·동의 기록을 다루고, 타인 비공개 녹음은 **메타데이터(길이·상태·용량)만 보며 전사 본문은 읽지 못한다**(삭제 요청 처리는 가능).

## 3. 작업 계약
공통 AI 작업 계약(jobs·job_steps 컬럼·상태 전이·재시도=새 작업·환불 멱등 키): [../contracts/JOBS.md](../contracts/JOBS.md). STT 고유:
| 항목 | 값 |
|---|---|
| 테이블 | `stt_jobs` · `stt_job_steps` |
| kind | `transcribe` · `summarize` |
| step 순서 | normalize · chunk · transcribe(조각별 마스킹 포함) · merge · diarize · summarize |
| 취소 단위 | 다음 조각 시작 전 취소 요청 확인 |
- 크레딧 연동은 선택이며 단가는 0.5크레딧/분(study-note 참고값, 제안, CORE_SPEC#4).

## 4. 파이프라인·엔진 규칙
| 항목 | 규칙 |
|---|---|
| 입력 | 브라우저 녹음(MediaRecorder)·파일 업로드 모두 FILE에 올린 뒤 `file_id`로 STT-A01. 허용 형식·크기는 FILE 규칙, 최대 길이는 설정 `max_duration_min`(기본 120분·제안값, 플랜 엔타이틀먼트가 덮어씀), 조직 동시 작업 기본 3개(제안값) |
| 처리 | 업로드/녹음 → 정규화(16kHz mono) → **5분 조각**(VOICE_ARCHITECTURE 기준) → 조각별 받아쓰기(병렬) → (선택) **조각 단위 마스킹**(이후 저장은 마스킹 후 결과만) → 병합 → (선택) 화자 구분 → (선택) 요약 → 편집. 진행률은 조각 수 기준. 요청당 STT 길이·파일 크기 한도는 플랫폼 제안값(VOICE_ARCHITECTURE#4) 확인 필요 |
| 엔진 | 기본 faster-whisper(MIT, GPU 자체 호스팅) · CPU·엣지 whisper.cpp(MIT) · 단어 타임스탬프·화자 구분은 WhisperX(BSD-2) + pyannote(모델 약관 확인 필요) 선택. 선택 근거 `adr.md` |
| 상용 API | 사용자 자기 신고(본인 발화 체크)는 쓰지 않고 **기능 경로로만** 판정한다. **마이크 직접 녹음 + 60초 이하(제안값) + 짧은 음성 입력 기능(음성 질문·음성 메모)** 이면서 조직 설정에서 외부 허용이 켜져 있고 국외 이전 동의 기록이 있을 때만. 요약 LLM도 같은 조건. 조건은 `api.md` 서버 내부 규칙 |
| 항상 자체 호스팅 | **파일 업로드·회의·강의 녹음 경로**는 항상 오픈소스 자체 호스팅, 국외 이전 금지(study-note 01_PRD#6.2 규칙 재사용). 재받아쓰기(A09)의 엔진 변경도 같은 규칙 |
| 용어집 | 사용 중 용어를 initial prompt로 전달. 효과는 벤치마크로 측정(`adr.md`) |
| 보관 | 원본 음성 기본 **7일 후 삭제**(설정, 0=즉시). 전사문은 조직 보관 정책(미설정이면 유지). 주민번호 등 패턴 자동 마스킹 옵션은 **조각 단위**로 적용해 `original_text`와 재시도용 임시 결과도 마스킹 후만 저장(임시 결과 TTL 24시간) |
| 사용량 | 분 단위 기록(`audio_seconds` 기준). 단가·크레딧 연동은 선택 |
| 제외 | 실시간 스트리밍 받아쓰기(2단계) |

## 5. 다른 모듈과의 경계
| 모듈 | 관계 |
|---|---|
| files-storage | 입력 음성·내보내기 파일의 저장소. 이 모듈은 `file_id`만 참조. 원본 삭제·서명 URL은 FILE 규칙 사용. FILE의 `file.object.deleted`를 구독: 처리 중 작업은 취소하고 완료된 전사는 유지하되 원본 참조(`file_id`)만 제거 |
| auth-rbac | `stt:use` · `stt:manage` 권한 판정. 서비스 키는 워커·음성 서버 호출 전용 |
| notify | `stt.transcript.completed`·`failed`를 구독. 수신자 = `payload.requested_by`. 본문·연락처 원문 없음 |
| admin-audit | 같은 이벤트와 설정 변경 같은 운영 행위를 `audit_log`에 기록 |
| core AI 라우팅·크레딧 | 요약 LLM은 `resolve_ai_route`, 크레딧은 선차감-환불(선택, CORE_SPEC#4) |
| rag-chat 등 소비 모듈 | 완료 이벤트를 받아 전사를 가져가 색인하는 일은 받는 모듈 몫. 본문은 이벤트에 없고 STT-A05로 읽는다 |

| 동의 기록 | 누가·언제·어떤 문구 버전에 동의했는지 `stt_recordings`에 저장, STT-S10에서 점검 *(보관 기간 확인 필요)* |

| 보관·파기 | 원본 기본 7일 삭제, 전사문은 조직 정책, 삭제 요청은 STT-A03 DELETE로 처리 *(법정 보관 기간과 충돌 여부 확인 필요)* |
| 주민번호 등 | 전사 저장 전 패턴 마스킹 옵션, 마스킹 전 원문은 저장하지 않는다 *(개인정보보호법 제24조의2 확인 필요)* |
| 모델·라이선스 | whisper 계열 코드·가중치 MIT, pyannote 모델은 약관 동의 필요 *(원문 확인 필요, 유료 서비스 사용 가능 여부 포함)* |
| AI 생성 표시 | 요약·전사에 "AI 생성·오류 가능" 안내 상시 표시 *(표시 의무 범위 확인 필요)* |

## 7. 보안 (security-baseline 연결 — 위협 메모)
이 모듈은 **사용자가 올린 파일을 서버가 디코딩·추론하는 면**과 **음성·전사라는 개인정보**를 다룹니다. 보안 레벨은 PRD 8절에서 정하되 L1 이상 권장.
| 항목 | 결정 |
|---|---|
| 노출 면 | 음성 업로드·녹음 입력(FILE 경유), 내보내기 서명 URL, 워커 → 음성 서버 호출, 이벤트 전달, 설정·동의 기록 화면 |
| 인증·인가 | 같은 조직 구성원만. 비공개 전사 본문은 작성자 본인만(음성 관리자 포함 타인 불가, 관리자는 메타데이터만). 음성 서버는 EdDSA 서명 토큰만 받고 공유 비밀키가 없다(VOICE_ARCHITECTURE#4) |
| 다루는 데이터 | 음성(file_id 참조)·전사 본문·화자 이름·동의 기록·IP 해시. 연락처 없음 |
| 필요한 키·권한 | 서비스 키(워커) · 음성 서버 토큰 서명 키(서버만) · 상용 API 키(허용할 때만·서버 환경변수) · 이벤트 서명 비밀키(구독자별) |
| 입력 | 확장자 + 매직 바이트 + 크기 + 길이 검사(FILE). 전사문은 요약 LLM에서 **데이터로만** 취급(프롬프트 주입 방지, 도구 호출 없음) |
| 체인 | 악성 오디오 → 디코더·추론 서버 취약점 → 서버 침해. → 음성 서버를 별도 컨테이너·비루트·외부 통신 제한으로 격리, 입력 길이 제한. 전사문 속 지시문 → 요약 LLM 오동작. → 지시와 데이터 분리 + 결과를 저장만 하고 실행하지 않음 |
| 피해 범위 | 서비스 키 유출 시 작업·전사 쓰기 → 서버 전용·분리. 서명 URL 유출 시 해당 파일 → 짧은 만료 |
| 남용 | 작업 생성·요약·내보내기 레이트 리밋, 조직별 동시 작업 수 상한(GPU 점유 방지), 길이·크기 상한 |
| 로그 | 작업 전이·동의·설정 변경은 감사 이벤트. 전사 본문·음성 URL·토큰은 로그 금지 |
| 결정 | 기본 자체 호스팅·외부 전송 금지, 외부 경로는 기능 경로 조건(마이크 직접·60초 이하·짧은 음성 입력 기능)만, 업로드·회의·강의는 외부 불가, 동의 없는 작업 생성 불가 |

## 9. 벤치마킹 메모 (모두 확인 필요 — 공식 문서로 재확인 전에는 사실로 쓰지 않는다)
| 제품 | 차별점 |
|---|---|
| OpenAI Whisper | 99개 언어 · 코드·가중치 MIT(확인 필요). API는 상용 |
| faster-whisper | CTranslate2 기반 고속 추론, MIT. 버전 1.2.x(2025-10 확인, 최신 확인 필요) |
| whisper.cpp | GPU 없이 CPU·엣지, MIT. 최신 버전 출처 상충(1.8.6 vs 1.9.1) |

## 10. 확정된 결정
